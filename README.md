## 📌 Project Overview

This repository documents the full software engineering lifecycle for a **Wedding Hall Reservation System** — a secure, web-based platform that enables customers to browse, book, and manage wedding hall reservations online. The system supports multiple user roles including guests, registered customers, hall managers, venue staff, administrators, customer support agents, and a finance manager.

The project is developed by **Group 6 (Developers)** serving **Group 5 (Customer)**.

## 📂 Phase Descriptions

### 🔹 Phase 0 – Initiation: Group Formation & Project Planning

This phase covers the formation of the development team and the selection of the business project.

**Tasks:**
- **Task 0.1** – Group Formation: Formed a team of 5 students with clearly defined roles (Project Manager, Requirement Engineer, Technical Architect, Programmer, QA).
- **Task 0.2** – Business Selection: Selected the *Wedding Hall Reservation System* as the project, a web-based application with security requirements (user authentication, payment processing, role-based access control).

**Management Strategy:** Weekly meetings (online via WhatsApp/Zoom + face-to-face). Final decisions made by the Project Manager after group discussion.

---

### 🔹 Phase 1 – Business Definition

This phase contains the business description outline provided by the customer group (Group 5), which informed the development team's understanding of the system.

**Tasks:**
- **Task 1.1** – Business Description Outline: A 1–2 page document describing the Wedding Hall Reservation business — its services, capacity, business processes, stakeholders, and operational environment.

**Key Deliverable:** Business description document (PDF) submitted by the customer group and shared with the development team.

---

### 🔹 Phase 2 – Requirements Engineering: Elicitation & Discovery

Based on the business description and meetings with the customer group, the development team elicited and documented the full requirements of the system.

**Tasks:**
- **Task 2.1** – User Requirements: A list of 6–10 high-level user requirements, each representing a distinct business service or function.
- **Task 2.2** – System Requirements: Detailed system-level requirements derived from each user requirement, specifying precise system behaviour and constraints.
- **Task 2.3** – Effort + Time Estimation: Estimation of the effort, cost, and time required to develop the system, based on the defined requirements.

**Includes:** Minutes of meetings with the customer group (dates, attendees, topics discussed).

---

### 🔹 Phase 3 – Requirements Analysis & Modelling

This phase translates the elicited requirements into formal UML models.

**Tasks:**
- **Task 3.1** – Actor Analysis: Identification and semantic description of all system actors (human and system).
- **Task 3.2** – Use-Case Modelling: Full use-case list and an overall UML Use-Case Diagram.
- **Task 3.3** – Use-Case Specifications: Detailed descriptions of 4–5 key use cases (one per group member), including flow of events, pre/post-conditions, alternatives, and error flows.
- **Task 3.4** – Activity Modelling: An overall UML Activity Diagram using swimlanes, showing how system use cases interact to deliver the main business services.

**UML Tool Used:** [Lucidchart]
